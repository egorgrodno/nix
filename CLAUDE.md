# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

NixOS configuration on flakes and home-manager for two hosts — `fractal` (desktop) and `thinkpad` (laptop) — built from shared modules and roles.

## Common Commands

Helper scripts from `modules/nixtools/`:

```bash
nxs   # nixos-rebuild switch --flake /etc/nixos  (apply configuration)
nxc   # nixos-rebuild build --flake /etc/nixos   (build without activating)
nxb   # nixos-rebuild boot --flake /etc/nixos    (build and add boot entry, no activation)
nxt   # nixos-rebuild test --flake /etc/nixos    (activate temporarily, no boot entry)
nxu   # nix flake update --flake /etc/nixos      (update flake.lock)
nx-setup  # per-user setup after the first boot: logins, identity, plugins; safe to rerun
```

`nxe` opens `home.nix` in a kitty window, so it ships with `modules/desktop/` rather than `modules/nixtools/`.

```bash
nix flake check /etc/nixos    # validate flake, formatting included
nix flake show /etc/nixos     # show outputs
nix fmt                       # format the tree
```

`treefmt.nix` defines the formatters: nixfmt for `*.nix`, stylua for `*.lua`, shfmt for shell. Markdown is deliberately excluded and stays hand-formatted against the conventions below.

A pre-commit hook in `.githooks/` rejects a commit whose staged files are not formatted, and reformats them in place so recovering is `git add` and commit again. It runs `nix fmt`, so it cannot drift from `checks.formatting` or from the editor.

## Architecture

### Entry point

`flake.nix` builds one `nixosConfiguration` per directory in `hosts/`, named after it, which also sets `networking.hostName`. Each host's `host.nix` supplies its users and `system.stateVersion`. Every host passes the same `specialArgs` — `theme`, `fontPackages`, `users`, `forAllUsers`, `inputs` — to every module. Home-manager is integrated as a NixOS module, not standalone. `homeConfigurations` (`neovim-qwerty`, `neovim-hallmack`) are standalone profiles for non-NixOS machines.

### Layer structure

```
flake.nix
  ├── hosts/<hostname>/host.nix            # users + stateVersion (data)
  └── hosts/<hostname>/configuration.nix   # hardware + role import
        └── roles/role-*-config.nix        # module bundles
              └── modules/*                # reusable feature modules (all users)

users/<name>.nix                           # identity + optional homeModules
  └── profiles/*.nix                       # home-manager profiles (one user)
```

### Key directories

- `hosts/` — One directory per machine, named as its hostname: `host.nix` (data the installer writes: `users`, `stateVersion`), `configuration.nix` (system settings, screens, graphics driver), and `hardware-configuration.nix` (generated by `nixos-generate-config`; kernel modules, microcode). Hand-written configuration goes in `configuration.nix`. The hardware file **must not** set `fileSystems`, which `role-base-config.nix` owns.
- `roles/` — Module bundles. `role-base-config.nix` declares the `base.*` options and forwards `keyboardLayout` and `isDesktop` to home-manager. See `roles/README.md`.
- `modules/` — Feature modules. Each owns both its NixOS and home-manager configuration, applying `hm.nix` to every user through `forAllUsers`.
- `profiles/` — Home-manager profiles attached to a single user. See `profiles/README.md`.
- `users/` — One file per user: `name`, `homedir`, `stateVersion`, optional `homeModules`. A host lists them by name in `host.nix`; the flake imports them into `specialArgs.users`.
- `pkgs/` — Flake packages, one directory each: a `writeShellApplication` in `default.nix` and its script beside it. `checks` builds them, so shellcheck runs under `nix flake check`. `install` and `repair-boot` run as root from a NixOS ISO; `nx-setup` reaches every user through `modules/nixtools`.
- `lib/` — Pure helper functions, not modules: each file takes `lib` and returns a value, and is used with `import ../../lib/<name>.nix lib`. Nothing here reads `config` or sets an option.
- `home.nix` — Generates each `home-manager.users.*` entry: identity plus that user's `homeModules`.

### Multi-user architecture

Users are declared in `users/*.nix` and listed by name in each host's `host.nix`, from which the flake builds `specialArgs.users`:

```nix
users = [
  "egor"
  "forge"
];
```

- **System accounts.** Roles generate `users.users.<name>` through `forAllUsers`.
- **Module fan-out.** An enabled module configures every declared user; the role decides which modules are enabled.
- **Per-user profiles.** `homeModules` attaches a profile to one user — the single-user complement to `forAllUsers`.

### Desktop role

`roles/role-desktop-config.nix` imports `modules/desktop/`: Hyprland on Wayland, with a bar, greetd/tuigreet, pipewire, dunst, GTK/cursor theming, and XDG MIME associations. The wallpaper is runtime state — `waypaper` sets it, Hyprland restores it with `waypaper --restore`.

**Bar.** `my.desktop.bar` selects `waybar` (default) or `quickshell`; its systemd user unit has the same name, which `$mod SHIFT R` restarts. `barHeight` in `modules/desktop/` is the strip either bar reserves, and a window docked under a bar module takes offsets measured off the selected bar. `modules/quickshell/` keeps its QML beside the module and generates `Theme.qml` from `theme` and `barHeight`, and `Programs.qml` with store paths, since the user service has no useful PATH.

**Idle.** hypridle dims, locks, and runs `suspend-then-hibernate` after the minutes of idle below, by the profile TLP last applied; a host without TLP takes the performance row. The suspend turns the screen off, and trails a lock in the same minute by 5 s. One hypridle runs every profile's listeners, since a restart would drop the D-Bus idle inhibits it holds. A listener runs its step once the step is due under the active profile, so a profile change mid-idle can delay a step to the performance row but never skip it. A fullscreen window inhibits idle. A host **must** declare swap at least the size of RAM in `swapDevices`; an assertion enforces its presence.

| Profile | Dim | Lock | Suspend | Hibernate |
|---|---|---|---|---|
| performance | 10 | 15 | 20 | 30 |
| balanced | 3 | 5 | 5 | 15 |
| power-saver | 1 | 2 | 2 | 7 |

**Hardware belongs to the host.** The module enables `hardware.graphics` and sets `NIXOS_OZONE_WL`; the video driver, VA-API backend, and vendor session variables are the host's. Screens likewise:

| `my.desktop` option | Meaning |
|---|---|
| `primaryScreen` | Connector name; defaults to `eDP-1`. Always emitted first, at `0x0`. |
| `primaryMode` | `2560x1440@120`, or `preferred` / `highres` / `highrr`. |
| `extraMonitors` | Hyprland strings for the remaining outputs, appended after the primary. |

### Laptop role

`roles/role-laptop.nix` enables `modules/power/` and sends lid close to `suspend-then-hibernate`.

**Profiles.** TLP applies `performance`, `balanced` and `power-saver` but never picks one (`TLP_AUTO_SWITCH=0`). `power-profile-sync` picks on every power_supply event, every minute, and after each TLP start: performance on AC, balanced on battery, power-saver at or below 20%. A choice made through tlp-pd holds until the next plug event. Power-saver hibernates 5 minutes after suspend; an `ExecStartPre` on `systemd-suspend-then-hibernate.service` writes that drop-in at suspend time.

**Charge limit.** `charge-limit on|off` holds the battery between 75% and 80%, on unless `/var/lib/charge-limit/off` exists. A polkit rule lets the active session start `charge-limit@on` and `charge-limit@off`, so it needs no sudo.

### Theme

`theme` (colors, fonts) is defined in `flake.nix` and reaches modules as a module argument. One Dark, with `Inconsolata LGC Nerd Font Mono` and `Overpass Nerd Font`.

### Hosts

- `fractal` — AMD/NVIDIA hybrid, NVIDIA PRIME sync, `HDMI-A-2` at `2560x1440@120`; users `egor` and `forge`. Dual-boots Windows, which boots from its own ESP (`WINBOOT`, `nvme1n1`) but keeps its D: (`WINDISKD`) on the NixOS disk, so a reinstall **must** use the installer's reuse mode rather than wipe `nvme0n1`.
- `thinkpad` — AMD, `eDP-1`, qwerty, portable GRUB, `role-laptop.nix`; user `egor`.
- Both track `nixos-unstable`. `role-base-config.nix` mounts `/` (ext4, `NIXROOT`) and `/boot` (vfat, `NIXBOOT`) by label on every host, so a reinstall must label its partitions to match. `wheel` has passwordless sudo. Both run sshd with password authentication disabled.

## Documentation conventions

These govern every Markdown file here.

- **Brevity.** Say it once, in the fewest words that stay precise. Prefer a table or a snippet to a paragraph. Cut what the code already tells the reader.
- **Document the contract, not the history.** State what the configuration is and what a change must satisfy. No changelogs, migration notes, or rationale for settled decisions.
- **Explain *why* only where it is non-obvious and load-bearing** — a workaround, a footgun, a value that looks wrong but is not. One sentence, and a code comment beats a doc paragraph.
- **Third person, present tense, declarative.** Never "I" or "we".
- **Bold lead-in** names a new concept, then one or two sentences.
- **`must` / `should`** mark real requirements, not emphasis.
- **Domain-fluent.** Nix vocabulary unglossed: flake, derivation, `specialArgs`, role, generation, activation.
- **Unwrapped.** One physical line per paragraph. Tables and code blocks keep their natural structure.

No first person, hedging, emoji, or contractions.
