# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

NixOS configuration on flakes and home-manager for two hosts — `fractal` (desktop) and `thinkpad` (laptop) — built from shared modules and roles.

## Common Commands

Helper scripts from `modules/nixtools/`:

```bash
nxs   # nixos-rebuild switch --flake /etc/nixos  (apply configuration)
nxc   # nixos-rebuild build --flake /etc/nixos   (build without activating)
nxb   # nixos-rebuild boot --flake /etc/nixos    (build and add boot entry, no activation)
nxt   # nixos-rebuild test --flake /etc/nixos    (activate temporarily, no boot entry)
nxu   # nix flake update --flake /etc/nixos      (update flake.lock), then craft-update
nx-setup  # per-user setup after the first boot: logins, identity, plugins; safe to rerun
```

`nxe` opens `home.nix` in a kitty window, so it ships with `modules/desktop/` rather than `modules/nixtools/`.

```bash
nix flake check /etc/nixos    # validate flake, formatting included
nix flake show /etc/nixos     # show outputs
nix fmt                       # format the tree
```

`treefmt.nix` defines the formatters: nixfmt and deadnix for `*.nix`, deadnix removing unused bindings and arguments, stylua for `*.lua`, shfmt for shell, gofmt for Go, and rumdl for Markdown. rumdl fixes mechanics only, with `.rumdl.toml` turning off its line-length rule; the prose conventions below stay by hand.

A pre-commit hook in `.githooks/` rejects a commit whose staged files are not formatted or carry dead Nix code, and fixes them in place so recovering is `git add` and commit again. It runs `nix fmt`, so it cannot drift from `checks.formatting` or from the editor, whose `<leader>f` runs nixfmt alone while nil marks the dead code deadnix removes.

## Architecture

### Entry point

`flake.nix` builds one `nixosConfiguration` per directory in `hosts/`, named after it, which also sets `networking.hostName`. Each host's `host.nix` supplies its users and `system.stateVersion`. Every host passes the same `specialArgs` — `theme`, `fontPackages`, `users`, `forAllUsers`, `inputs` — to every module. Home-manager is integrated as a NixOS module, not standalone. `homeConfigurations` (`neovim-qwerty`, `neovim-hallmack`) are standalone profiles for non-NixOS machines.

### Layer structure

```text
flake.nix
  ├── hosts/<hostname>/host.nix            # users + stateVersion (data)
  └── hosts/<hostname>/configuration.nix   # hardware + role import
        └── roles/role-*-config.nix        # module bundles
              └── modules/*                # reusable feature modules (all users)

users/<name>.nix                           # identity + optional homeModules
  └── profiles/*.nix                       # home-manager profiles (one user)
```

### Key directories

- `hosts/` — One directory per machine, named as its hostname: `host.nix` (data the installer writes: `users`, `stateVersion`), `configuration.nix` (system settings, screens, graphics driver), and `hardware-configuration.nix` (generated by `nixos-generate-config`; kernel modules, microcode). Hand-written configuration goes in `configuration.nix`. The hardware file **must not** set `fileSystems`, which `role-base-config.nix` owns.
- `roles/` — Module bundles. `role-base-config.nix` declares the `base.*` options and forwards `keyboardLayout` and `isDesktop` to home-manager. See `roles/README.md`.
- `modules/` — Feature modules. Each owns both its NixOS and home-manager configuration, applying `hm.nix` to every user through `forAllUsers`.
- `profiles/` — Home-manager profiles attached to a single user. See `profiles/README.md`.
- `users/` — One file per user: `name`, `homedir`, `stateVersion`, optional `homeModules`. A host lists them by name in `host.nix`; the flake imports them into `specialArgs.users`.
- `pkgs/` — Flake packages, one directory each: a `writeShellApplication` in `default.nix` and its script beside it, or a `buildGoModule` for a tool that parses more than shell holds well. `checks` builds them, so shellcheck and the Go tests run under `nix flake check`. `install` and `repair-boot` run as root from a NixOS ISO; `nx-setup` reaches every user through `modules/nixtools`, `craft-update` through `modules/craft`, and `carve` through `modules/git`. `carve` splits the working tree's changes into commits by hunk, in a scratch worktree with hooks, for the commit skill; `carve apply -h` documents the plan.
- `lib/` — Pure helper functions, not modules: each file takes `lib` and returns a value, and is used with `import ../../lib/<name>.nix lib`. Nothing here reads `config` or sets an option.
- `home.nix` — Generates each `home-manager.users.*` entry: identity plus that user's `homeModules`.

### Multi-user architecture

Users are declared in `users/*.nix` and listed by name in each host's `host.nix`, from which the flake builds `specialArgs.users`:

```nix
users = [
  "egor"
  "forge"
];
```

- **System accounts.** Roles generate `users.users.<name>` through `forAllUsers`.
- **Module fan-out.** An enabled module configures every declared user; the role decides which modules are enabled.
- **Per-user profiles.** `homeModules` attaches a profile to one user — the single-user complement to `forAllUsers`.

### Desktop role

`roles/role-desktop-config.nix` imports `modules/desktop/`: Hyprland on Wayland, with a Quickshell bar, notification daemon, lock screen and greeter on greetd, pipewire, GTK/cursor theming, and XDG MIME associations. `xdg.userDirs` declares the user directories, which activation creates and GTK bookmarks, `Pictures/Screenshots` and `Pictures/Wallpapers` among them. The wallpaper is runtime state, which awww draws and the wallpaper picker sets.

**Bar.** Quickshell runs as the `quickshell` systemd user unit, which `$mod SHIFT R` restarts. It draws two bars on every screen: the window title, workspaces, network and the notification bell on top, and along the bottom the apps menu, cpu, ram and disk in the left corner and the status modules in the right. The tray leads the status modules in a segment of its own, so a new icon grows into the empty middle and moves no other module. A submap's name slides out from under the workspaces into their segment, and back. `barHeight` in `modules/desktop/` is the strip each reserves, and `outerGap` the windows' outer gap. pwvucontrol docks over the bottom bar, centred on the volume module by an offset measured off the bar, unless that would cross the outer gap. `modules/quickshell/` keeps its QML beside the module and generates `Theme.qml` from `theme`, `barHeight` and `outerGap`, and `Programs.qml` with store paths, since the user service has no useful PATH. A program the bar opens starts through `uwsm app`, in a scope of its own: a child of the unit dies when the bar restarts. Quickshell reports reloads as transient notifications rather than through its own popup.

**Quickshell's look.** Segments of related modules sit inside each strip, their outer edges on the windows' outer gap. Figures take fixed-width `fontMono` slots, so a changing reading never shifts the modules beside it. Meters are grey, and colour marks state: blue for focus, a connected Bluetooth device and a VPN that is up, yellow and red for warnings, red for a muted speaker or microphone, green for charging.

**Panels.** The power and network panels are layer surfaces built on `Panel.qml`, placed against the bar as they open, centred on their module unless that would cross the outer gap, and left there while the module changes width. The monitor panel and the wallpaper picker, which have no module, centre on their screen, under the top bar and over the bottom one. Escape or a click outside closes them, through Hyprland's focus grab. Hyprland hands the keyboard to the focused window whenever another layer surface unmaps, grab or not, so the newest panel takes it back with a new grab; an exclusive surface would keep it, but takes the pointer too, and a click outside would never reach the grab. They **must not** be grabbing popups: Hyprland drops a popup's grab whenever another layer surface unmaps, so an expiring notification would close one. Panels sit on the `overlay` layer above the notification popups, which an `order` layer rule puts beneath them, and an open panel holds the popups' timers. A panel slides `Theme.slide` out of the bar as it fades in, and back, and eases to a new height when its content changes, inside a surface that spans the strip between the bars: Hyprland draws a resize in flight by stretching the last frame, so a panel's surface **must not** resize. Hyprland's own layer animation is off for it. Panels and notification popups cast a shadow over the windows, reaching `Theme.shadow` past the box, which their surfaces leave room for. Tooltips slide the same way, clipped at their window's edge: a window reaching over the module would take the hover off it.

**Notifications.** `Notifications.qml` runs Quickshell's `NotificationServer`, and a D-Bus service file starts `quickshell.service` for a notification sent while the bar is down. Popups stack newest first in the focused screen's top right, at most five, on `overlay` so a critical one shows over a fullscreen window. Each runs its own timer, which hovering holds: the app's timeout, else 5 s for low, 15 s for normal, and never for critical. A click runs the default action or dismisses; a right-click, a drag right, or `$mod grave` dismisses, and `$mod SHIFT grave` dismisses every popup. A card whose sender takes a reply has a field for one, in the popups and the panel alike. A click on it takes the keyboard and holds the card's timer until Enter sends, which closes the notification, or Escape or a click outside gives the keyboard back. A popup with the same `x-dunst-stack-tag`, `synchronous` or `x-canonical-private-synchronous` hint is replaced in place, as `replaces_id` does.

**Notification panel.** The bell in the top bar's right corner counts what arrived since its panel last opened, red while one of them is critical, and turns into a blue crossed-out bell under do-not-disturb. A click or `$mod CTRL grave` opens the panel; a right-click toggles do-not-disturb. The panel groups entries by `desktopEntry`, else `appName`, the latest app first; while it is open a dismissal moves no group, and only a new notification moves its group to the top. From two entries a group has a header with the app's icon, name and count, which opens or closes it, and a button that clears it. Every group starts open, and a closed one shows only its newest card. A popup that times out moves into the panel and stays with its sender, actions included, until dismissed, invoked or withdrawn; a transient one closes instead. Under do-not-disturb or over a fullscreen window on the focused workspace only a critical notification pops up, and while the panel is open none does; the rest go straight to the panel. Going fullscreen sends the popups already up there too, critical ones aside. The newest 100 entries and do-not-disturb persist in Quickshell's state directory, with an `image-data` image, or an image file outside the store, saved as a PNG once a card has shown it, so a restart keeps everything but the actions. A browser deletes its notification images as it exits, and a picture that no longer loads is left out.

**OSD.** `Osd.qml` shows the volume, the microphone's mute, the brightness or Caps Lock for a second, centred above the bottom bar on the focused screen. The audio binds and a release bind on `Caps_Lock` raise it through `quickshell ipc call osd volume|mic|caps`, and the brightness keys through `quickshell ipc call backlight up|down`, which steps the backlight 10%, never below 1%; the bar's scroll, pwvucontrol and the power panel, which show the value themselves, do not. Caps Lock is read from Hyprland's main keyboard.

**Power panel.** Where UPower reports a laptop battery, a click on Quickshell's battery module opens a panel: charge, with the band the charge limit holds, and time to empty or full, profile buttons through tlp-pd, a brightness slider through brightnessctl, an adaptive backlight slider, and a charge-limit toggle that starts `charge-limit@on|off`. Entering power-saver saves the backlight level and dims to 30%, never brightening; leaving it restores the saved level. The slider overrides at any time. The saved level lives in Quickshell's state directory, so a bar restarted mid-power-saver neither dims again nor forgets it.

**Night light.** wlsunset warms the screen at night unless `~/.local/state/night-light` is non-empty, which skips its unit. The Appearance panel's toggle writes `off` there and stops the unit, or empties the file and starts it, so the choice holds across logins.

**Network.** Quickshell's network module shows the connection (Wi-Fi in four strength steps, Ethernet, or none), a VPN shield wherever a VPN or WireGuard profile exists, and a minute of upload and download, each its own graph beside its rate. A click opens a panel: a Wi-Fi switch, the networks in range with connect, an inline password prompt for WPA-PSK and SAE, disconnect, stop while connecting, forget on a second click, Ethernet, a switch per VPN and WireGuard profile through nmcli, and nm-connection-editor for everything else, which a right-click also opens. A network first set up from the panel whose first connection fails is forgotten, so NetworkManager never retries a wrong key, and the module reopens its panel to ask for the password again. nm-applet runs only as NetworkManager's secret agent, which asks for VPN, 802.1X and changed Wi-Fi secrets; `Tray.qml` hides its icon. NetworkManager carries the OpenVPN plugin; WireGuard is built in.

**Bluetooth.** Quickshell's Bluetooth module leads volume. A click soft-blocks or unblocks every Bluetooth radio through rfkill, as `btoff` and `bton` do. On the thinkpad the block cuts the radio's power and BlueZ drops the adapter, so the module reads rfkill as well and shows wherever a Bluetooth rfkill switch or adapter exists. A right-click opens blueman-manager, which runs blueman's applet, and with it the pairing agent, only while it is open, and without a tray icon of its own. The block survives a reboot, through systemd-rfkill on fractal and TLP's `RESTORE_DEVICE_STATE_ON_STARTUP` on a laptop; both restore Wi-Fi's block too.

**Session menu.** A click on the ⏻ module, or `$mod 0` through `quickshell ipc call session toggle`, opens a panel of the session's actions, each run by a click or its key: `l` lock, `u` suspend, `h` hibernate, `e` log out, `r` reboot, and `S` shut down, which takes Shift so Caps Lock alone never sends it. No row starts selected; only the pointer highlights one. Hibernate shows only under `base.hibernate`. Log out ends the graphical login session through `loginctl terminate-session auto`, with or without uwsm, and leaves SSH sessions alone. `$mod SHIFT 0` locks directly.

**Lock screen.** `Lock.qml` holds the session lock through ext-session-lock, inside the bar: on every screen the wallpaper blurred and dimmed, the time over the date, and a login card with the password as dots, which PAM's `quickshell-lock` service checks. `my.quickshell.lockCommand` locks, as hypridle's `lock_cmd`, and so `loginctl lock-session` and the session menu, and `$mod SHIFT 0` run it. It writes a flag naming the Hyprland instance in the runtime directory before the IPC call, and starts the bar should it be down; a bar started under the flag, after a crash or `$mod SHIFT R`, takes the lock back, which `misc:allow_session_lock_restore` allows. A bar that dies under the lock leaves the session locked on a plain colour. hypridle's `inhibit_sleep = 3` holds a suspend until Hyprland reports the session locked; its default does so only for a `lock_cmd` naming hyprlock.

**Greeter.** greetd runs `start-hyprland` with a config of its own: the `my.desktop` monitor rules, the session's input and cursor, and Quickshell's greeter from `modules/quickshell/greeter/`, which shares `Theme.qml` and the login card with the lock screen. Every screen shows it; Up and Down step the user, Tab the session, and F11 or F12, pressed twice, reboot or shut down. `logins.json`, built from the normal users and the wayland-sessions entries, lists both, and a launch passes `XDG_SESSION_DESKTOP`, `DESKTOP_SESSION` and `XDG_CURRENT_DESKTOP` as tuigreet did. The last user and each user's last session persist under the greeter's home, `/var/lib/greeter`; a user without one gets `services.displayManager.defaultSession`, the uwsm-managed Hyprland. Quickshell exits on the launch, and its Hyprland after it. The bar copies its kept layouts to `/var/lib/monitor-layouts/<user>.json`, a file the user owns in a directory root does, and the greeter loads the last user's into its own `Monitors.qml`, so it lays the screens out as the session does, clamshell included, and fades in once that layout has applied. A rebuild never restarts greetd, so a greeter change shows at the next boot.

**Launcher.** The apps button in the bottom bar's left corner, or `$mod D`, opens the launcher on its apps, `$mod Y` on the clipboard and `$mod period` on symbols; the bind for the mode showing closes it. A full-screen layer of its own dims the screen behind it, beneath the popups, fading in and out with the launcher. Tab and Shift Tab change the mode, Up and Down the selection, and Enter runs it. Apps match by name, generic name, keywords and id, ranked by use, each launch's weight halving every two weeks; with no query the five most used lead the full list. Right opens an app's desktop actions. Apps start through `uwsm app`, which opens a `Terminal=true` entry in kitty by `xdg.terminal-exec`. The clipboard mode lists cliphist's history, an image as a thumbnail; Enter copies an entry back and Shift Delete forgets it. The symbols mode finds emoji and Nerd Font glyphs by name, the recent ones first, and Enter copies one. `symbols.json` is built from `unicode-emoji` and Nerd Fonts' `glyphnames.json`, whose release **should** match the fonts'. App use and recent symbols persist in Quickshell's state directory.

**Displays.** `$mod SHIFT S`, or Displays in the launcher, opens the monitor panel on the focused screen: each monitor in use as a box at its logical size, dragged into place and snapped edge to edge, and for the one selected its resolution, refresh rate, scale, rotation, mirror and power. It offers the scales at which the mode is a whole number of logical pixels. Apply tries the layout through `hyprctl eval` and reverts it after 15 s unless kept. A kept layout is saved per set of connected monitors, keyed by their descriptions, in Quickshell's state directory. `Monitors.qml` applies it whenever that set connects and after every config reload, which restores the `my.desktop` defaults; a set that connects with none saved raises a notification that opens the panel. A layout that moves or resizes the cursor's monitor takes the cursor along, to the same place on it. The monitors come from `hyprctl monitors all`, as every other view drops a disabled one. A monitor rule keeps whatever its predecessor set that it leaves out, so every spec applied **must** set `disabled` and `mirror`. A set's Stay awake switch holds a systemd `idle` inhibitor while that set is connected, which hypridle honours: no dim, lock or suspend.

**Appearance.** `$mod SHIFT W`, or Appearance in the launcher, opens a strip of `~/Pictures/Wallpapers` over the bottom bar on the focused screen, png and jpg, the one showing ringed and the one applied checked. Moving to one shows it at once behind the windows, awww's circle growing out of its tile; Enter or a click on the ringed tile keeps it, and any other close sets back the applied one, the circle closing back into the tile it grew from. The wheel or a drag scrolls the strip without previewing. Below it, Light and Dark set the color scheme and a toggle the night light, both at once, which no close reverts. Open folder opens the folder in pcmanfm, making it if it is missing. awww's daemon, a user unit Quickshell starts, restores each output's image at login from a cache keyed by awww's version, so an update empties it. `Wallpapers.qml` therefore saves the one kept in Quickshell's state directory and gives it to any output showing another, at start and when the folder changes; with none kept, an output without an image gets the first wallpaper to arrive. A second after a layout applies or a monitor connects, it sends every output its image again: awww redraws a resized output from its cache, sized for a scale the output passes through, and drops what does not fit.

**Curtain.** At the session's first start `Curtain.qml` covers every screen in `Theme.backgroundMain`, the colour of Hyprland's `misc.background_color`, on `overlay` above every other layer, and fades it out once `Monitors.qml` has applied the saved layout and awww has drawn the wallpaper after it, so the scale jump and the first draws happen unseen; after 3 s it lifts regardless. Hyprland's `cursor:invisible` hides the pointer from Hyprland's start until the fade starts, or for 10 s should the bar never get that far, and a bar restarted after dying under the curtain clears it. A bar restarted in the same Hyprland instance skips it, by the instance signature saved in Quickshell's state directory. The session does not start awww: Quickshell starts it once the curtain maps, or at once without one, as a wallpaper drawn first would vanish under it. Each lift, and what it still waited for, goes to the `quickshell` unit's journal.

**Clamshell.** While the lid is closed and a monitor besides the laptop's panel is on in the open lid's layout, `Monitors.qml` turns the panel off and leaves it out of the set, which keeps a layout of its own; opening the lid restores the open lid's. logind then counts the laptop as docked and ignores the lid. Losing the last other monitor ends clamshell after a 3 s grace, which rides out a TV blinking off, and turns the panel back on. A `handle-lid-switch` inhibitor, held while the lid is closed and the panel off, keeps logind from suspending before that. The lid state is logind's `LidClosed`. `Monitors.qml` logs the lid, each set, clamshell, both inhibitors, every layout it applies and any Hyprland rejects to the `quickshell` unit's journal.

**Idle.** hypridle dims, locks, and suspends after the minutes of idle below, by the profile TLP last applied; a host without TLP takes the performance row. The suspend turns the screen off, and trails a lock in the same minute by 5 s. One hypridle runs every profile's listeners, since a restart would drop the D-Bus idle inhibits it holds. A listener runs its step once the step is due under the active profile, so a profile change mid-idle can delay a step to the performance row but never skip it. In clamshell the suspend step only turns the screens off, and input turns them on again. Before any sleep hypridle moves the pointer a pixel and back, which restarts the idle timers, so a step nearly due at the suspend does not run the moment the machine wakes: Hyprland counts no wake, not even the lid, as input. A suspend that a block-mode sleep lock refuses, as Claude Code's awake plugin holds through a turn, waits for the lock to go, unless input ends the idle first: hypridle never asks again. A fullscreen window inhibits idle.

| Profile | Dim | Lock | Suspend | Hibernate |
|---|---|---|---|---|
| performance | 10 | 15 | 20 | 30 |
| balanced | 3 | 5 | 5 | 15 |
| power-saver | 1 | 2 | 2 | 7 |

**Hibernation.** Under `base.hibernate` every suspend, from idle, the lid or the session menu, is `suspend-then-hibernate`, which hibernates after `HibernateDelaySec`; without it a suspend stays one, and the table's last column does not apply. The option **requires** swap at least the size of RAM in `swapDevices`; an assertion enforces its presence.

**Hardware belongs to the host.** The module enables `hardware.graphics` and sets `NIXOS_OZONE_WL`; the video driver, VA-API backend, and vendor session variables are the host's. Screens likewise:

| `my.desktop` option | Meaning |
|---|---|
| `primaryScreen` | Connector name; defaults to `eDP-1`. Always emitted first, at `0x0`. |
| `primaryMode` | `2560x1440@120`, or `preferred` / `highres` / `highrr`. |
| `extraMonitors` | `hl.monitor` specs for the remaining outputs, appended after the primary. |

**Craft apps.** `modules/craft/` installs the [Craft apps](https://github.com/storytold) for every user from their own Linux tarballs, patched for the store rather than compiled, each with the `<app>-cli` that serves MCP. `sources.json` pins each app's version and hash; `craft-update`, which `nxu` runs, moves every key to its latest release, and a new app enters as a key with an empty object. Each generation keeps the tarballs, so rebuilding the pinned versions needs no GitHub. The apps open the office formats and their own; PDF, SVG, images and video stay with the viewers in `modules/desktop/`. The Claude Code config's `craft` plugin registers the MCP servers.

### Laptop role

`base.isLaptop` turns on `roles/role-laptop.nix`, which enables `modules/power/` and sends lid close to the same suspend as idle. The flag also pins `hostnamectl chassis` to `laptop`, by which dev mode holds off idle, sleep and the lid switch while anything is unlocked.

**Profiles.** TLP applies `performance`, `balanced` and `power-saver` but never picks one (`TLP_AUTO_SWITCH=0`). `power-profile-sync` picks on every power_supply event, every minute, and after each TLP start: performance on AC, balanced on battery, power-saver at or below 20%. A choice made through tlp-pd holds until the next plug event. Power-saver hibernates 5 minutes after suspend; an `ExecStartPre` on `systemd-suspend-then-hibernate.service` writes that drop-in at suspend time.

**Charge limit.** `charge-limit on|off` holds the battery between 75% and 80%, on unless `/var/lib/charge-limit/off` exists. A polkit rule lets the active session start `charge-limit@on` and `charge-limit@off`, so it needs no sudo.

**Adaptive backlight.** TLP sets amdgpu's ABM (`panel_power_savings`) with each profile: 0 in performance, 1 in balanced, 3 in power-saver. It lowers the backlight below the level brightnessctl reports and brightens the pixels to make up for it. `adaptive-backlight@<0-4>` sets a level until the next profile change, and the same polkit rule lets the session start it.

### Theme

`theme` is defined in `flake.nix` and reaches modules as a module argument: `Inconsolata LGC Nerd Font Mono` and `Overpass Nerd Font`, and two palettes under the same names, `dark` (One Dark) and `light` (One Light). A color added to one **must** be added to the other; `Theme.qml` fails to build otherwise. Foreground tones run from `strong`, the bar's text, to `faint`; `black`, `white` and `bright` are the terminal's.

**Color scheme.** `color-scheme light|dark|toggle` saves the scheme in `~/.local/state/color-scheme`, then sets Hyprland's borders and background through `hyprctl eval`, and GTK's theme, icons and `color-scheme` in dconf. Without an argument it sets the saved one again, as every home-manager activation does after `dconfSettings`. The portal hands `color-scheme` on to libadwaita, the browsers and kitty, whose `*-theme.auto.conf` files hold both palettes; kitty tells the programs inside, and Neovim sets `background`, which reloads onenord. Vivaldi's Operating System theme schedule reads `vivaldi.system.desktop_theme_color`, which its Linux build never sets, so a script patched into its UI's `window.html` sets it from `prefers-color-scheme`. Hyprland's config reads the file at load and Quickshell's `Theme.qml` follows it, so the curtain and Hyprland's background still match. `quickshell ipc call theme toggle|light|dark` runs the command. The `org/gnome/desktop/interface` dconf group is forced, as the gtk module would set the theme and icons at every switch; the greeter stays dark.

### Hosts

- `fractal` — AMD/NVIDIA hybrid, NVIDIA PRIME sync, `HDMI-A-2` at `2560x1440@120`; users `egor` and `forge`. Dual-boots Windows, which boots from its own ESP (`WINBOOT`, `nvme1n1`) but keeps its D: (`WINDISKD`) on the NixOS disk, so a reinstall **must** use the installer's reuse mode rather than wipe `nvme0n1`.
- `thinkpad` — AMD, `eDP-1`, qwerty, portable GRUB, `base.isLaptop`; user `egor`. `touchpad-reset` rebinds a touchpad that lost its click, and `wifi-reset` reloads ath11k when the Wi-Fi card stops completing handshakes.
- Both track `nixos-unstable`. `role-base-config.nix` mounts `/` (ext4, `NIXROOT`) and `/boot` (vfat, `NIXBOOT`) by label on every host, so a reinstall must label its partitions to match. A weekly `nh clean` keeps a generation while it is one of the last 10 or under 90 days old, and GRUB lists at most 20, since `NIXBOOT` is 1 GiB. `wheel` has passwordless sudo. Both run sshd with password authentication disabled, and both set `base.hibernate` with a swapfile the size of RAM.

## Documentation conventions

These govern every Markdown file here.

- **Brevity.** Say it once, in the fewest words that stay precise. Prefer a table or a snippet to a paragraph. Cut what the code already tells the reader.
- **Document the contract, not the history.** State what the configuration is and what a change must satisfy. No changelogs, migration notes, or rationale for settled decisions.
- **Explain *why* only where it is non-obvious and load-bearing** — a workaround, a footgun, a value that looks wrong but is not. One sentence, and a code comment beats a doc paragraph.
- **Third person, present tense, declarative.** Never "I" or "we".
- **Bold lead-in** names a new concept, then one or two sentences.
- **`must` / `should`** mark real requirements, not emphasis.
- **Domain-fluent.** Nix vocabulary unglossed: flake, derivation, `specialArgs`, role, generation, activation.
- **Unwrapped.** One physical line per paragraph. Tables and code blocks keep their natural structure.

No first person, hedging, emoji, or contractions.
