# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

NixOS configuration on flakes and home-manager for two hosts — `fractal` (desktop) and `thinkpad` (laptop) — built from shared modules and roles.

## Common Commands

Helper scripts from `modules/nixtools/`:

```bash
nxs   # nixos-rebuild switch --flake /etc/nixos  (apply configuration)
nxc   # nixos-rebuild build --flake /etc/nixos   (build without activating)
nxb   # nixos-rebuild boot --flake /etc/nixos    (build and add boot entry, no activation)
nxt   # nixos-rebuild test --flake /etc/nixos    (activate temporarily, no boot entry)
nxu   # nix flake update --flake /etc/nixos      (update flake.lock), then craft-update
nx-setup  # per-user setup after the first boot: logins, identity, plugins; safe to rerun
nx-iso    # build the rescue stick's ISO and print its path; see rescue/README.md
nx-flash  # write that ISO, or another, over a USB stick picked from a list, then verify it
```

`nxe` opens `home.nix` in a kitty window, so it ships with `modules/desktop/` rather than `modules/nixtools/`.

```bash
nix flake check /etc/nixos    # validate flake, formatting included
nix flake show /etc/nixos     # show outputs
nix fmt                       # format the tree
```

`treefmt.nix` defines the formatters: nixfmt and deadnix for `*.nix`, deadnix removing unused bindings and arguments, stylua for `*.lua`, shfmt for shell, gofmt for Go, and rumdl for Markdown. rumdl fixes mechanics only, with `.rumdl.toml` turning off its line-length rule.

A pre-commit hook in `.githooks/` rejects a commit whose staged files are not formatted or carry dead Nix code, and fixes them in place so recovering is `git add` and commit again. It runs `nix fmt`, so it cannot drift from `checks.formatting` or from the editor, whose `<leader>f` runs nixfmt alone while nil marks the dead code deadnix removes.

## Architecture

### Entry point

`flake.nix` builds one `nixosConfiguration` per directory in `hosts/`, named after it, which also sets `networking.hostName`. `nixosConfigurations.rescue` is the rescue stick, not a host: its `specialArgs` hold only `inputs`, and it has no home-manager. Each host's `host.nix` supplies its users and `system.stateVersion`. Every host passes the same `specialArgs` — `theme`, `fontPackages`, `users`, `forAllUsers`, `inputs` — to every module. Home-manager is integrated as a NixOS module, not standalone. `homeConfigurations` (`neovim-qwerty`, `neovim-hallmack`) are standalone profiles for non-NixOS machines.

### Layer structure

```text
flake.nix
  ├── hosts/<hostname>/host.nix            # users + stateVersion (data)
  └── hosts/<hostname>/configuration.nix   # hardware + role import
        └── roles/role-*-config.nix        # module bundles
              └── modules/*                # reusable feature modules (all users)

users/<name>.nix                           # identity + optional homeModules
  └── profiles/*.nix                       # home-manager profiles (one user)
```

### Key directories

- `hosts/` — One directory per machine, named as its hostname: `host.nix` (data the installer writes: `users`, `stateVersion`), `configuration.nix` (system settings, screens, graphics driver), and `hardware-configuration.nix` (generated by `nixos-generate-config`; kernel modules, microcode). Hand-written configuration goes in `configuration.nix`. The hardware file **must not** set `fileSystems`, which `role-base-config.nix` owns.
- `roles/` — Module bundles. `role-base-config.nix` declares the `base.*` options and forwards `keyboardLayout` and `isDesktop` to home-manager. See `roles/README.md`.
- `modules/` — Feature modules. Each owns both its NixOS and home-manager configuration, applying `hm.nix` to every user through `forAllUsers`.
- `profiles/` — Home-manager profiles attached to a single user. See `profiles/README.md`.
- `users/` — One file per user: `name`, `homedir`, `stateVersion`, optional `homeModules`. A host lists them by name in `host.nix`; the flake imports them into `specialArgs.users`.
- `pkgs/` — Flake packages, one directory each: a `writeShellApplication` in `default.nix` and its script beside it, or a `buildGoModule` for a tool that parses more than shell holds well. `checks` builds them, so shellcheck and the Go tests run under `nix flake check`. `install` and `repair-boot` run as root from a NixOS ISO. The rescue stick carries the copies it was built with, so a change to either needs a new stick. `nx-setup`, `nx-iso` and `nx-flash` reach every user through `modules/nixtools`, `craft-update` through `modules/craft`, and `carve` through `modules/git`. `carve` splits the working tree's changes into commits by hunk, in a scratch worktree with hooks, for the commit skill; `carve apply -h` documents the plan. `gum` wraps nixpkgs' gum in the colors of `lib/gum-theme.nix`, and an overlay in `flake.nix` makes it `pkgs.gum` for the hosts, the rescue stick and every package here.
- `lib/` — Pure values and helper functions, not modules. A helper takes `lib` first and is used with `import ../../lib/<name>.nix lib`. Nothing here reads `config` or sets an option.
- `home.nix` — Generates each `home-manager.users.*` entry: identity plus that user's `homeModules`.
- `rescue/` — The rescue stick's NixOS module and login cheat sheet. See `rescue/README.md`.

### Multi-user architecture

Users are declared in `users/*.nix` and listed by name in each host's `host.nix`, from which the flake builds `specialArgs.users`:

```nix
users = [
  "egor"
  "forge"
];
```

- **System accounts.** Roles generate `users.users.<name>` through `forAllUsers`.
- **Module fan-out.** An enabled module configures every declared user; the role decides which modules are enabled.
- **Per-user profiles.** `homeModules` attaches a profile to one user — the single-user complement to `forAllUsers`.

### Desktop role

`roles/role-desktop-config.nix` imports `modules/desktop/` and `modules/craft/`; `modules/desktop/` imports `modules/quickshell/`.

| Module | Holds |
|---|---|
| `modules/desktop/` | Hyprland and the session around it: hypridle, greetd, the color scheme, window rules, MIME associations, the user directories |
| `modules/quickshell/` | The bar, its panels, notifications, OSD, launcher, lock screen, and the greeter's QML |
| `modules/craft/` | The [Craft apps](https://github.com/storytold), each with the `<app>-cli` that serves MCP, pinned in `sources.json` |

`modules/desktop/` and `modules/quickshell/` each have a `CLAUDE.md`, which loads once a file beneath it is read.

### Theme

`theme` is defined in `flake.nix` and reaches modules as a module argument: two fonts, and the `dark` (One Dark) and `light` (One Light) palettes. The palettes **must** hold the same color names: `Theme.qml` takes each name from `dark` and looks it up in `light`, so a name missing from `light` fails evaluation and one only in `light` is dropped. `color-scheme light|dark|toggle` switches between them at runtime.

### Hosts

- `fractal` — AMD/NVIDIA hybrid, the session on the NVIDIA card; users `egor` and `forge`. Dual-boots Windows, which boots from its own ESP (`WINBOOT`, `nvme1n1`) but keeps its D: (`WINDISKD`) on the NixOS disk, so a reinstall **must** use the installer's reuse mode rather than wipe `nvme0n1`.
- `thinkpad` — AMD, `eDP-1`, qwerty, portable GRUB, `base.isLaptop`; user `egor`. `touchpad-reset` rebinds a touchpad that lost its click, and `wifi-reset` reloads ath11k when the Wi-Fi card stops completing handshakes.
- Both track `nixos-unstable`. `role-base-config.nix` mounts `/` (ext4, `NIXROOT`) and `/boot` (vfat, `NIXBOOT`) by label on every host, so a reinstall must label its partitions to match. A weekly `nh clean` keeps a generation while it is one of the last 10 or under 90 days old, and GRUB lists at most 20, since `NIXBOOT` is 1 GiB. `wheel` has passwordless sudo. Both run sshd with password authentication disabled, and both set `base.hibernate` with a swapfile the size of RAM.
